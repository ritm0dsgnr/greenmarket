# Green Market

Проект интернет-магазина садового центра.

В репозитории создана основа production-приложения: Next.js 16.3, React 19,
TypeScript в строгом режиме, Sass, проверка серверной конфигурации, PostgreSQL
миграции и базовые автоматические проверки. Это ещё не готовый магазин: здесь
нет каталога, базы с данными, Excel-импорта, WordPress, авторизации, заявок,
корзины, бонусов или внешних интеграций.

Архитектурные границы и порядок развития находятся в
[docs/PROJECT_STACK.md](docs/PROJECT_STACK.md), правила для агентов: в
[AGENTS.md](AGENTS.md), решение по foundation: в
[docs/adr/0001-production-foundation.md](docs/adr/0001-production-foundation.md).
Полный пакет передачи в разработку: [docs/DEVELOPMENT_HANDOFF.md](docs/DEVELOPMENT_HANDOFF.md).

## Локальный запуск

Требуется Node.js 24.19.0 или более новый релиз ветки 24.x. Требование
зафиксировано в `.node-version` и проверяется до запуска скриптов.

```bash
npm install
npm run dev
npm run check
```

`npm run start` предназначен для production-процесса и требует реальные
`DATABASE_URL` и `APP_BASE_URL` только из защищённого окружения. Подробности
первого развёртывания: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Ключевые проектные решения

- Публичный сайт развивать в сторону Next.js + React + TypeScript.
- Каталог товаров хранить в базе данных приложения, а Excel использовать только как источник безопасного импорта.
- Новости, статьи, слайдеры, акции и SEO-поля редактировать через админку/CMS.
- CMS для редакционного контента: WordPress в headless-режиме. WordPress не используется для каталога, цен, Excel-импорта, корзины или пользователей приложения.
- Бонусную систему хранить на сервере; Telegram-бот может быть интерфейсом, но не источником истины.
- Функции, работающие с данными, деньгами, доступом или внешними сервисами, реализуются только по утверждённым этапам на серверной стороне Next.js.
- Прайс `Для сайта Прайс ГринМаркет.xlsx` не требует отдельного ID: сервис использует внутренний отпечаток строки только для предварительного сопоставления, а спорные обновления всегда проходят через ручную проверку.
- UI следует BEM-подобным классам и Sass-модулям по компонентам. Повторяемые UI-иконки хранятся в SVG-спрайте и подключаются через `<use>`.
